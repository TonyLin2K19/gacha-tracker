# 需求紀錄

## v0.3.1 已修正：HTTP 環境新增池期失敗（2026-10-09 新增，優先修正）

- 切換卡池選擇新增時，出現 `crypto.randomUUID is not a function`，阻止建立新池期。
- 一般卡池與鋼嵐套裝池的新增入口皆直接呼叫瀏覽器 `crypto.randomUUID()`；應移除對安全環境專屬 API 的依賴，優先由後端產生池期 ID。
- 保持既有池期 ID、紀錄歸屬及保底計算不變。
- 使用一般區網 HTTP 網址測試兩種新增入口，不可只用 localhost 或 HTTPS 驗證。

## v0.3.1 已改善：深色模式下拉選單展開出現大片白底（2026-10-09 新增）

- 使用者在「切換套裝池」展開原生下拉選單時，選項後方／下方出現大片白色區域，影響表單閱讀。
- 依使用者截圖重現並檢查原生 select 的 color-scheme、選項背景，以及彈窗的捲動與合成繪製；已補上深色 color-scheme 與選項配色；使用者瀏覽器的原生彈出繪製仍需部署後確認。
- 修正後驗證展開、選取與收合均無白底殘留，並檢查其他下拉選單及深／淺色模式。

## v0.3.1 已完成：欄位顯示設定依遊戲保存（2026-10-09 新增）

- 總覽的欄位顯示／隱藏設定依遊戲 ID 分開保存，不再全遊戲共用。
- 切換遊戲時恢復該遊戲的欄位選擇；修改一個遊戲不影響其他遊戲。
- 支援各遊戲不同稀有度與適用欄位，避免不適用的欄位被其他遊戲的設定帶入。
- 更新時保留既有欄位偏好，處理舊版全域設定的相容與初始化。

以下歷史項目已於 v0.3.0 實作並驗證。

## 所有卡池支援換池與保底繼承設定（2026-10-09 定案，下次一起實作）

- 每一個卡池都可換池，不另設「是否允許換池」開關。
- 換池時可選既有池期或新增具名池期，名稱可記錄此次 UP 角色／卡池主題。
- 抽卡紀錄歸屬到當時的池期，保留池期名稱、各期抽數與出貨歷史，也保留跨池期總累積統計。
- 另設「換池時繼承保底」開關：開啟時沿用保底進度，關閉時新池期從零開始；不刪除舊紀錄。
- 明日方舟基本尋訪與限定尋訪分開統計：基本尋訪開啟繼承，限定尋訪關閉繼承。
- 鋼嵐機甲仍使用共用保障標記與各池獨立階段的既有規則，不可被一般歸零／繼承開關覆蓋。
- 實作時明確處理切回舊池期的進度與必 UP 狀態，避免將「新增池期」和「切回既有池期」混為同一種重設操作。
- 既有未命名的池期預設名稱為「卡池一」；已有名稱的池期保留原名，既有抽取紀錄歸屬原池期。
- 卡池名稱可隨時編輯以修正輸入錯誤；更名只更新名稱，不改變池期識別、紀錄歸屬或保底進度。
- 統一提供另外的卡池列表，顯示池期名稱與編輯入口，可查看該池的抽取紀錄及統計。
- 個別池期統計與跨池期總累積統計並存。

## 稀有度配色（2026-10-09 記錄，下次一起實作）

- 四種稀有度依最高到最低：彩色、黃（金）色、紫色、綠色。
- 平常三種稀有度：SSR = 黃（金）色、SR = 紫色、R = 綠色。
- 四種稀有度依等級順序套用，不限制稀有度名稱。
- 四級名稱可能是 UR 等自訂名稱，或明日方舟的六星／五星／四星／三星；後者依序對應彩／金／紫／綠。
- 彩色文字可用 CSS 靜態漸層；目前為設計建議，具體呈現尚未定案。
- 此配色用於稀有度顯示；最近出貨的歪／不歪／保底狀態配色仍依既有規則。

## 刪除遊戲與卡池（2026-10-08 記錄，下次一起實作）

- 補上介面的「刪除遊戲」功能，讓使用者能完整移除示範遊戲。
- 刪除遊戲或刪除卡池，都必須手動輸入大寫 `DELETE` 才能確認。
- 確認視窗清楚顯示刪除對象與影響範圍；未完整輸入 `DELETE` 時不可執行刪除。
- 實作時處理遊戲底下仍有卡池與紀錄的情況；目前後端會拒絕刪除含卡池的遊戲。
- 刪除卡池或遊戲前，都自動備份一次完整 DB；備份成功後才執行刪除，備份失敗則中止刪除。
- 取消確認或未完整輸入 `DELETE` 時，不執行備份或刪除。

刪除前同時產生完整 SQLite DB 與可由介面匯入的 JSON 備份，保存於 `/data/backups`。
