# 星願旅記 GACHA JOURNEY · v0.3.0

v0.3.0：換套裝池改為下拉選單，可切回以前的套裝池或新增套裝池。機甲仍保留同一列與累計資料，各套裝池分別保存 9／12／15 次十連階段與整機必 UP 狀態。舊版換池紀錄自動列入選單，不清除或改寫舊抽卡歷史。

首次使用新版切換時，請勾選「校正進度」，對照遊戲填共用保障標記與目前池的階段；例如舊版顯示 60／150，只能暫作 6 個標記、第 15 次十連階段的參考，實際標記以遊戲為準。沒有詳細紀錄的以往池，可新增後校正階段。校正是一筆可編輯／刪除的切換紀錄，不修改累計數量與歷史出貨。

啟用新版標記計算後，非最高稀有度整機十連增加 1 個標記；最高稀有度整機扣除當前池的門檻，餘額保留、最低為 0。單抽不增加整機保障標記。切回舊池恢復該池階段與整機必 UP，55 抽部件墊底進度保留；部件必 UP 按套裝池分別保留。最近整機出貨間隔與保障標記分開計算。首次啟用前的舊版統計保持原計算方式，不推測歷史標記餘額。

v0.2.1：完整總覽提供浮動固定於底部的快速記錄列，支援原有數量、稀有度、快速十抽、詳細與撤銷操作。表格預留工具列高度，避免遮住最下方資料。最近出貨間隔依詳細紀錄顯示：歪為紅色、UP（不歪）為綠色；未標示 UP／歪時，保底為橘色，其餘維持原色。舊歷史基底沒有每次出貨結果，因此不猜測紅／綠色。套裝保底依出貨當時的門檻判斷。

以密集表格管理多遊戲、多伺服器、多帳號與卡池。React + TypeScript + shadcn/ui 的 Radix 元件模式 + Tailwind CSS + TanStack Table；Express + Node.js 內建 SQLite。單容器部署到 Unraid，桌機只需 Chrome。

## Unraid 啟動

1. 解壓縮專案到例如 `/mnt/user/appdata/gacha-tracker-source`。確認該目錄內有 Dockerfile 與 compose.yaml。
2. 開啟 Unraid Terminal，準備資料目錄（預設使用 Unraid nobody:users）：

```bash
mkdir -p /mnt/user/appdata/gacha-tracker
chown 99:100 /mnt/user/appdata/gacha-tracker
chmod 770 /mnt/user/appdata/gacha-tracker
cd /mnt/user/appdata/gacha-tracker-source
docker compose up -d --build
```

3. 瀏覽器開啟 `http://你的Unraid-IP:3080`。

初次建置會下載 Node 映像與 npm 依賴，後續電腦無須啟動 Node。若 3080 已使用，更改 compose.yaml 左側連接埠。appdata 建議放在 SSD pool，避免容器運作時由 mover 搬動 SQLite 檔案；若要直接指定 `/mnt/cache/...`，請依你的實際 pool 名稱修改掛載。

若 Unraid 尚未提供 `docker compose`，可直接執行以下等效命令，不必先安裝 Compose：

```bash
cd /mnt/user/appdata/gacha-tracker-source
docker build -t gacha-tracker:0.3.0 .
docker run -d --name gacha-tracker --restart unless-stopped --init \
  --user 99:100 -p 3080:3000 -e TZ=Asia/Taipei \
  -v /mnt/user/appdata/gacha-tracker:/data \
  --log-opt max-size=10m --log-opt max-file=3 \
  gacha-tracker:0.3.0
```

本版供可信任的家用內網使用，未加入登入帳號；連得到此網址的人可讀寫資料。遠端使用請透過你自己的 VPN 或具驗證的反向代理。

## 第一次使用

1. 新增遊戲。
2. 新增帳號卡池：填伺服器、帳號、卡池名稱，設定稀有度與機率（總和 100%，最高稀有度放第一列）。
3. 展開「歷史起始資料」，填舊 Sheet 的 SSR/SR/R 等數量、目前墊抽、UP／歪次數、已知出貨間隔。
4. 主畫面選取該列，用快速按鈕新增，預設 +1，可自訂數量。
5. 用「詳細」新增混合結果、選 UP／歪、輸入時間與備註。

遊戲編輯頁可上傳 PNG／JPG／WebP 圖示並調整顯示順序。完整總覽頂端仍可切換遊戲；伺服器、帳號與卡池篩選可交叉使用。瀏覽器會記住最後查看的遊戲，下次重新整理會直接回到該遊戲。

沒有任何正式或截圖推測資料預載。空白頁的「載入虛構示範資料」只會在點擊後建立一個標示為示範的遊戲，供熟悉操作。範例不是實際遊戲機率。

## 舊 Google Sheets 多列匯入

點「匯入基底」，選擇規則範本（也可使用預設機率）。將舊表整理成一張帶有以下標題的表格，複製儲存格，連同標題貼入。欄位順序可調；稀有度名稱必須與規則一致。

| 伺服器 | 帳號   | 卡池 | SSR |  SR |   R | 累計 | 墊抽 |  UP |  歪 | 下次必UP | 出貨間隔 |
| ------ | ------ | ---- | --: | --: | --: | ---: | ---: | --: | --: | -------- | -------- |
| 台服   | 主帳號 | 機師 |   2 |  10 |  88 |  100 |   20 |   1 |   1 | 是       | 30,50    |

- 必填標題：伺服器、帳號、卡池、各稀有度。其他欄可省略；稀有度空格當作 0。
- 若有「累計」，會檢查是否等於各稀有度總和，防止貼錯欄。
- 墊抽空白代表未知；「下次必UP」接受「是／否／未知」，空白代表未知。
- 出貨間隔順序為**舊 → 新**，以逗號分隔。原 Sheet 的 last、last2 等若從新到舊排列，需先反轉順序。
- 不會自動猜測截圖欄位、不同機制或缺失資料。
- 一批套用一套規則，不同規則可分批匯入；匯入後仍可編輯各池。
- 只新增卡池，不覆蓋原資料；同遊戲／伺服器／帳號／卡池重複時整批拒絕。
- 所有列先驗證，再在單一交易中寫入，避免只匯入一半。

## 記錄與統計定義

- **總抽數／稀有度數量**：歷史基底 + 所有 draw 紀錄。
- **出貨率**：最高稀有度數量 ÷ 總抽數。**平均抽數**：總抽數 ÷ 最高稀有度數量。
- **快速 R +10**：十次連續 R，不是未知結果的十連抽。混合十連請用詳細／混合批次。
- 混合批次每行 `稀有度,數量,結果`；結果為 `up`、`off`、`unknown`，可省略。
- 勾選「已知順序」代表每行依序發生、該行數量為連續相同結果。例如 R,6 → SSR,1,up → R,3，結束墊抽為 3。
- 不知順序且含最高稀有度時，墊抽保守標為未知；下次已知出貨後恢復精確。未知間隔不硬填數字，最近間隔僅列已知值。
- **額外獎勵**不計入抽數、出貨率、UP／歪統計，也不重置保底。可開啟額外獎勵欄顯示數量。
- **硬保底次數**只統計詳細紀錄中確定恰好到達門檻的出貨；不推算舊歷史或未知間隔。
- **基礎期望**僅為總抽數 × 基礎機率，未含保底；預設隱藏。
- 線性軟保底：從起始抽數當抽開始加一次 softStep（百分點），以後每抽再加，最高 100%；硬保底門檻當抽為 100%。
- 下抽機率是依設定的模型計算，不會強制改寫真實結果；若遊戲不是線性軟保底，請不要套用。
- 歪後必 UP：最高稀有度明確標 off 後開啟；明確標 up 後解除；未註明則未知。單筆混合多個出貨且順序未知時保守推算，不猜最後一張。
- 同遊戲／伺服器／帳號 + 相同「保底共用群組」會共用墊抽、間隔及必 UP 狀態。數量與實際出貨率仍是每池獨立。第一版要求規則完全一致、無歷史基底，避免多池重複套用起始保底。
- **十抽保底、兌換里程碑及其他特殊機制目前保存為說明**，不自動計算或生成贈送紀錄。
- 編輯／刪除抽卡紀錄會按抽卡時間重新計算；同時間以新增序號排序。歷史起始基底固定視為所有詳細紀錄之前，補登時請避免與基底重複。
- 修改卡池規則會重算該池歷史；已有紀錄禁止改稀有度名稱與順序。規則不同的活動可複製設定建立新池。

## 備份與維護

側欄「資料與備份」可下載完整 JSON、在主機建立快照，或選擇備份並輸入 RESTORE 還原。還原取代所有資料，操作前自動保存一份原資料。

`/data/gacha.db` 是 SQLite 資料庫，搭配 WAL/SHM 檔運作；`/data/backups` 保存 JSON 快照，遊戲圖示存放於 `/data/game-icons`。服務每連續運作 24 小時建立自動備份，刪除卡池、還原前也會備份。JSON 快照不內嵌圖示檔，搬移主機時請連同整個 `/data` 目錄備份。快照目前不自動刪除，可依磁碟空間自行保留；同主機備份仍應定期複製到其他位置。

執行中請用應用程式的完整 JSON 備份，不要只複製 gacha.db 而漏掉 WAL。若需要整個資料目錄備份，可先停止容器再複製。

更新程式後執行 `docker compose up -d --build`，持久化掛載內容會保留。重新命名遊戲不影響其資料；新增帳號、伺服器直接在卡池表單輸入，現有值提供自動完成。

## 本機開發

需要 Node.js 24（使用內建 node:sqlite）。

```bash
npm ci
npm run dev
```

開啟 `http://localhost:5173`。Vite 代理 `/api` 到 Express 3000。資料預設放在 `data/`，可設定 DATA_DIR。

```bash
npm test
npm run build
npm start
```

正式服務預設 3000，可透過 PORT 調整。前後端與共享模型均為 TypeScript。

主要結構：

- `src/App.tsx`：密集總覽、篩選、快速記錄、歷史頁與備份介面。
- `src/Forms.tsx`：遊戲、卡池規則、基底與抽卡表單。
- `src/ImportForm.tsx`：Google Sheets 多列貼上、驗證與預覽。
- `src/components/ui`：可直接修改的 shadcn/Radix 風格基礎元件。
- `shared/model.ts`：資料型別、Zod 驗證與共用保底限制。
- `shared/stats.ts`：純函式統計，所有結果由基底與紀錄重算。
- `shared/import.ts`：TSV 基底匯入解析。
- `server/db.ts`：SQLite schema、交易、快照。
- `server/index.ts`：Express API 與靜態網頁服務。
- `tests/stats.test.ts`：統計、匯入、SQLite 交易與持久化測試。
